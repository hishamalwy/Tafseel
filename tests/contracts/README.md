# API contract gate

Checks that the Angular client calls routes, HTTP methods and request bodies the API actually
accepts. Two halves, both run in CI:

| File | Role |
|---|---|
| `api-endpoints.json` | Every controller endpoint the running host resolves: route, methods, access, and the JSON body it binds (field names, which are required). Generated by `ApiContractSnapshotTests`, which fails when the file no longer matches the API. |
| `dynamic-client-calls.json` | Angular calls whose URL is computed at runtime. Every computed call site must be acknowledged here; every snippet must still exist. |
| `api-contract-known-violations.json` | Violations that exist today, each with its remediation-matrix row. |
| `scripts/ci/check-api-contract.mjs` | Extracts every Angular API call and compares it with the snapshot. |

## What it catches

`NO_ROUTE`, `WRONG_VERB`, `SHADOWED` (a literal path segment swallowed by a route parameter),
`BODY_MISSING_REQUIRED`, `BODY_UNKNOWN_FIELD`, `BODY_NOT_ACCEPTED`, and `UNRESOLVED_CALL` (a
computed URL nobody declared).

It does not see: request bodies built in a variable rather than an object literal, query-string
parameters, response shapes, or a discriminator value that is well-formed but wrong (for example
`admin/catalog/educationLevels` where the API expects `education-levels`).

## Workflow

```bash
node scripts/ci/check-api-contract.mjs            # CI: fails on a new violation or a fixed one still listed
node scripts/ci/check-api-contract.mjs --strict   # fails on any violation
```

- **Changed an API endpoint on purpose?** Regenerate the snapshot and commit it with the change:
  `UPDATE_API_CONTRACT_SNAPSHOT=1 dotnet test tests/Tafseel.IntegrationTests --filter ApiContractSnapshotTests`
- **Fixed a known violation?** Delete its entry from `api-contract-known-violations.json` in the same change.
- **Added a call with a computed URL?** Declare it in `dynamic-client-calls.json`.
