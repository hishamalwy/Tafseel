# Tafseel product remediation

## Phase 1 — Money and trust

Goal: every paid transaction reaches a deterministic, auditable ending.

- [x] Release live-session escrow on completion and student no-show.
- [x] Refund live-session escrow on teacher cancellation/no-show and eligible student cancellation.
- [x] Enforce the configured cancellation window.
- [x] Snapshot live-session teacher commission at booking time.
- [x] Support live-session refunds in the shared refund ledger.
- [x] Auto-complete delivered orders after a 72-hour review window when no dispute is open.
- [x] Ship student, teacher, and admin dispute-center interfaces.
- [x] Publish versioned legal, cancellation, refund, academic-integrity, teacher, dispute, and escrow policies.
- [x] Add verified reviews for completed live sessions.
- [x] Require a manually verified payout/KYC profile before withdrawal and snapshot the masked destination.

Exit criteria: no confirmed payment can remain held without an automatic or human resolution path.

## Phase 2 — Student and teacher simplicity

Goal: users understand the next action without understanding Tafseel's internal model.

- [x] Route students between direct and open requests from one intent question.
- [x] Add a normalized offer-comparison view, included revisions, proposal validity, and configurable reservation expiry.
- [x] Add overdue and mutually accepted extension flows.
- [x] Add teacher withdrawal history and payout-status details.
- [x] Finish coupon entry and validation in checkout.
- [x] Consolidate teacher setup into grouped navigation and one readiness checklist.
- [x] Localize the complete live-session booking surface and detect time zone automatically.
- [x] Make closed conversations read-only after seven days, reopening case communication through an active dispute.

Exit criteria: both roles can finish their primary jobs from one clear task queue.

## Phase 3 — Retention and marketplace growth

Goal: increase repeat purchase and marketplace liquidity after the core cycle is reliable.

- [x] Rebook the same teacher for completed requests and terminal live sessions.
- [x] Save reusable request templates beyond the existing per-teacher draft.
- Multi-session bundles and recurring weekly bookings.
- Availability waitlists.
- [x] Calendar sync through a standards-compliant private ICS export.
- Offer/reply templates.
- [x] Proposal validity and included-scope fields.
- Referral credits and attributable campaigns.
- [x] Private teacher conversion, repeat-student, completion, and earnings analytics with CSV statements.
- [x] Transparent relevance matching; demand/supply alerts remain a growth experiment.
- [x] Academic-integrity classification and production-gated file security scanning.

The unchecked Phase 3 items are optional growth bets, not launch-readiness blockers. They must not bypass the settled payment, dispute, qualification, or consent cycles above.

Exit criteria: repeat rate, fill rate, and time-to-first-offer improve without increasing disputes or cancellations.
