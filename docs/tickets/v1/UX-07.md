## Actor
Visitor and signed-in users on the landing page.

## Problem
The landing page opens a promotion dialog on entry (`landing-page.component.ts:345-351`,
`landing-page.component.html:351-352`). The dialog renders the promotion's `couponCode` with «استخدم الكود» / "Use the
code" and a copy button (`promo-wizard.component.html:47-52`, `promo-wizard.component.ts:59,135-145`). Checkout has
**no coupon field**, so a student cannot redeem the code (Contract §9 row "Coupons", V1_SCOPE row J5-03,
`B11-08`).

`GET /api/v1/promotions` returns every live promotion with `kind` and `couponCode` (`PromotionDto`,
`MarketingContracts.cs:10-29`). The Development demo seed includes a `Discount` promotion: «خصم 20% على أول طلب لك»,
code `TAFSEEL20` (`DependencyInjection.cs:182-190`). The promise itself ("20% off") is unredeemable, not only the
code.

## User goal
As a visitor, I want every offer I see on Tafseel to be something I can actually use, so that I don't feel misled at
checkout.

## Business rule
- Coupons at checkout are **V1.1** (`DEC-09` open, non-blocking; default V1.1; `B11-08`). V1 checkout charges the
  price plus the fee per Contract §3.7.
- [UX_PRINCIPLES §2 / PRODUCTION_READINESS U10](../../product/UX_PRINCIPLES.md#2-rules): no dead or misleading
  controls.
- Therefore in V1 the client shows **no coupon code and no discount promotion**. Non-discount promotions (`Feature`,
  `Announcement`, `Spotlight`, `Event`) keep working.
- Backend coupon and promotion capabilities are **not removed**.

## Business states
| Promotion (`kind`, `couponCode`) | V1 landing behaviour |
|----------------------------------|----------------------|
| `Discount` (0), any code | Not shown (filtered out before choosing the entry dialog promotion) |
| Non-discount with a non-empty `couponCode` | Shown **without** the code field or copy button |
| Non-discount without code | Shown unchanged |
| No eligible promotion | No entry dialog (existing behaviour when the list is empty) |

## Preconditions
None.

## Happy path
1. A visitor opens `/ar` or `/en`.
2. The landing page fetches `GET /api/v1/promotions` (unchanged).
3. The client removes `Discount` promotions, then picks the entry-dialog promotion as today.
4. The dialog shows eyebrow, title, body, highlight and CTA — never a code field.

## Negative cases
| Case | Behaviour |
|------|-----------|
| Every live promotion is `Discount` | No entry dialog |
| An Admin creates a new Discount promotion in V1 | Still hidden on the landing (Admin promotion editing is not in V1 navigation — `UX-03`) |
| A campaign was dismissed earlier (`campaigns.dismiss` in local storage) | Unchanged |
| Promotions call fails | Existing behaviour (no dialog) |

## Authorization
`GET /promotions` is anonymous and unchanged. No data exposure change (the code is still in the public payload; the
client simply does not render it — it grants nothing because checkout cannot redeem codes).

## UX
- **Entry point:** landing page entry dialog.
- **Information hierarchy:** unchanged for non-discount promotions minus the code block.
- **Primary CTA per state:** the promotion's CTA (e.g. «جرّبها الآن») — unchanged.
- **Wording (AR / EN):** no new copy. Keys `promoCodeLabel` («استخدم الكود» / "Use the code") and `promoCopy` («نسخ» /
  "Copy") are no longer rendered (kept for V1.1).
- **Mobile (390px):** the dialog without the code block — verify no empty gap remains.
- **Loading / empty / error / not-available states:** unchanged.
- **Confirmation dialogs:** none.
- **Gate question:** yes — a visitor sees only offers they can act on.

## API contracts
No new API contract; presentation/composition only.

Unchanged and not called by V1 UI: `/api/v1/admin/promotions*`, `/api/v1/admin/coupons` (routes stay; tabs hidden by
`UX-03`).

Error codes the UI must explain: none.
