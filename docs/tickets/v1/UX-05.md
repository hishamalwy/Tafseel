## Actor
Visitor, Student, Teacher.

## Problem
Two user-facing paths exist for the same open-marketplace goals
([UX_PRINCIPLES §6.5](../../product/UX_PRINCIPLES.md#65-duplicated-paths-to-the-same-goal)):

| Goal | Old Wave 2 path (inline, on `/requests`) | Wave 3B path (canonical) |
|------|------------------------------------------|--------------------------|
| Student chooses an offer | `/requests?requestId=…` list + inline "Choose offer" (`marketplace-page.component.html:97-99`) | `/requests/:id/offers` |
| Teacher sends an offer | `/requests` teacher side, inline `.tf-market-offer-form` (`marketplace-page.component.html:113`) | `/teacher/opportunities/:id` |
| Post a request (header, footers, landing, about) | `/requests` (the marketplace list) | `/requests/new` (request-mode choice) |

Every "Post a request" link points to `/requests`: `public-header.component.html:10,44`,
`landing-footer.component.html:31`, `mini-footer.component.ts:20`, `landing-page.component.html:330`,
`landing-page.component.ts:136`, `product-story.component.html:13`, `about-page.component.html:58`.
The server's "Complete payment to keep your Offer" reminder links to bare `/requests` without the request
(`OpenMarketplaceService.cs:347-349`), so the student lands on a list instead of the request to pay.
The Development demo promotion "Post a request, let teachers come to you" also uses `AppRoutes.OpenRequests`
(`DependencyInjection.cs:198`).

## User goal
As a student, I want one way to post a request and one place to compare and choose offers; as a teacher, I
want one place to find open requests and send offers — so that I never meet two different screens for the
same job.

## Business rule
[Contract §4.2 Open Request](../../product/TAFSEEL_PRODUCT_CONTRACT.md#42-open-request-marketplace) and
§3.4–§3.5 (offers, selection, reservation) — unchanged. Only the screens that reach them change. No new rule.

## Business states
Unchanged: Open Request *Receiving offers* → *Offer held for payment* → *Became an order* (or back to
*Receiving offers* on release/expiry). Teacher Offer *Submitted* → *Selected* → *Accepted*.

## Preconditions
Wave 3B screens exist and are browser-proven (`wave3b-open-marketplace.e2e.mjs` 9/9): `/requests/new`,
`/requests/new/open`, `/requests/:id`, `/requests/:id/offers`, `/teacher/opportunities`,
`/teacher/opportunities/:id`.

## Happy path
**Canonical student path**
1. «اطلب شرحاً» / "Post a request" (header, landing, footers, Student navigation `UX-03`) → `/requests/new`.
2. Request-mode choice: «اطلب من معلم تختاره» / "Ask a teacher you choose" → `/teachers` → teacher profile →
   `/requests/new?…` (Direct Request), or «استقبل عروضًا من المعلمين» / "Receive offers from teachers" →
   `/requests/new/open`.
3. After publishing an Open Request → `/requests/:id` → «قارن العروض» → `/requests/:id/offers` → choose →
   `/checkout?learningRequestId=:id`.

**Canonical teacher path**
1. «طلبات مفتوحة» / "Open requests" (Teacher navigation `UX-03`; replaces "Post a request" in the header for a
   signed-in teacher) → `/teacher/opportunities`.
2. Open one → `/teacher/opportunities/:id` → send / edit / withdraw an offer.

## Negative cases
| Case | Behaviour |
|------|-----------|
| Old bookmark or stored notification `/requests` — student | Redirect → `/requests/new` |
| `/requests` — teacher | Redirect → `/teacher/opportunities` |
| `/requests` — visitor | Existing `authenticatedGuard` → sign-in → back to `/requests` → role redirect above |
| `/requests?requestId=X` — student | Redirect → `/requests/X` (the detail page already shows «قارن العروض» / pay) |
| `/requests?requestId=X` — teacher | Redirect → `/teacher/opportunities/X` (the request detail already does this for unassigned teachers) |
| `/requests?requestId=` with an invalid id | Redirect as if no id |
| Admin / Quality on `/requests` | Redirect to their home (`/admin/home`, `/quality/applications`) |
| Old reservation reminders already stored with `/requests` | Land on `/requests/new` (reminders are only relevant for ≤ 30 min, so no data migration) |
| Legacy `Tafseel-Open-Marketplace.dc.html` | Server legacy map still returns `/requests` → client role redirect (no server change) |

## Authorization
Unchanged. Redirects run after `authenticatedGuard`; destination routes keep their guards
(`roleGuard('Student')` on `/requests/new/open` and `/requests/:id/offers`, `roleGuard('Teacher')` on
`/teacher/opportunities/:id`). No new data is exposed.

## UX
- **Entry point:** header, landing CTA, footers, about page, notifications, Student and Teacher navigation.
- **Information hierarchy:** unchanged on the canonical screens.
- **Primary CTA per state:** unchanged on the canonical screens; header CTA is role-aware
  (visitor/student «اطلب شرحاً» → `/requests/new`; teacher «طلبات مفتوحة» → `/teacher/opportunities`).
- **Wording (AR / EN):** «اطلب شرحاً» / "Post a request"; «طلبات مفتوحة» / "Open requests". No other copy changes.
- **Mobile (390px):** the mobile header menu (`public-header.component.html:44`) gets the same role-aware link.
- **Loading / empty / error / not-available states:** redirects are synchronous route decisions (no flash of the
  old page).
- **Confirmation dialogs:** none.
- **Gate question:** yes — one path per goal; old links still arrive somewhere sensible.

### Routes to retire
| Route | Today | After |
|-------|-------|-------|
| `requests` (pathMatch full) → `MarketplacePageComponent` | Wave 2 inline list, choose and offer forms | Functional redirect (role- and `requestId`-aware) — the component is no longer routed |

The component files (`features/requests/pages/marketplace-page.component.*`) and `om_*` keys are **not
deleted** in this ticket; removal is later hygiene (`B11-16`) once nothing references them.

### Deep links that must keep working
`/requests/new` · `/requests/new/open` · `/requests/:id` · `/requests/:id/offers` · `/teacher/opportunities` ·
`/teacher/opportunities/:id` · `/checkout?learningRequestId=` · every server link built from `AppRoutes.Request`
and `AppRoutes.RequestOffers` (`OpenMarketplaceService.cs:132,216,379,382,404`; `OrderService.cs:60,140,151,162`) ·
`AppRoutes.OpenRequests` (`/requests`, redirect) · legacy `Tafseel-Open-Marketplace.dc.html` and
`Tafseel-Request.dc.html`.

### Server link fix (not protected code)
- `OpenMarketplaceService.cs:349`: reminder link `AppRoutes.OpenRequests` → `AppRoutes.Request(item.Id)`.
- `DependencyInjection.cs:198` (Development demo promotion seed only): `AppRoutes.OpenRequests` → `AppRoutes.NewRequest`.

## API contracts
No new API contract; presentation/composition only. The client stops calling the endpoints only the retired page
used (they remain on the server). The reminder notification's `link` value changes (`NotificationDto` shape
unchanged).

| UI action | Endpoint | Verb | Request | Headers / concurrency | Response | Resulting server state |
|-----------|----------|------|---------|-----------------------|----------|------------------------|
| Reminder notification is queued | (server job) `OpenMarketplaceService.RunAsync` | — | — | — | `NotificationDto.link = "/requests/{id}"` | notification row with the request link |
| Student compares/chooses offers | `/api/v1/open-marketplace/requests/{id}/offers`, `/…/offers/{offerId}/select` (existing, 3B) | GET / POST | unchanged | unchanged (`If-Match` request and offer versions) | unchanged | unchanged |
| Teacher sends an offer | `/api/v1/open-marketplace/opportunities/{id}/offers` (existing, 3B) | POST | unchanged | unchanged | unchanged | unchanged |

Error codes the UI must explain: unchanged (handled by the 3B screens: `offer_changed`/409, `offer_expired`,
reservation expiry).
