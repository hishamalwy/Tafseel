## Actor
Student and Teacher on a phone (390px) using Arabic.

## Problem
[UX_PRINCIPLES §2 rules 9–10](../../product/UX_PRINCIPLES.md#2-rules) require every customer journey to be verified in
Arabic at 390px. Wave 3B proved parts of the direct-order, open-marketplace, messaging and live-session journeys at phone
width, including:
- the sticky mobile pay CTA;
- file-name containment (`.tf-file-list`);
- the RTL back arrow.

Several V1 customer screens have never been checked in Arabic at 390px: teacher setup (profile, services, availability,
publication), booking, session checkout, disputes, and the request/offers/opportunity screens in all their states
(`V1_RELEASE_BLOCKERS` UX-06 row).

## User goal
As a student or teacher on my phone in Arabic, I want every screen I need to fit the screen, read naturally right-to-left
and show its main button, so that I can finish my task without zooming, scrolling sideways or meeting English words.

## Business rule
No business rule; verification of UX_PRINCIPLES §2 (rules 9, 10) and §3 (Saudi-first usability). **No redesign:** defects
are fixed inside the existing design system (spacing, wrapping, containment, direction, missing Arabic keys, tap-target
size). Anything needing a new layout or interaction becomes a new ticket.

## Business states
Screens are verified in the states below (seeded by `scripts/dev/E2ESeed` scenarios, extended where a state is missing).

### Matrix

- **H** — no horizontal scroll;
- **C** — no card/content overflow;
- **R** — correct RTL arrows and direction;
- **E** — no English UI terminology;
- **D** — readable currency, date and time;
- **T** — touch targets ≥ 44px;
- **P** — primary CTA visible (in viewport on load, or sticky).

### Assertion definitions (automated where marked ⚙)
- **H ⚙** `document.documentElement.scrollWidth ≤ window.innerWidth` after load and after each state change.
- **C ⚙** Every `.tf-card`, list item, dialog and file row is contained in its parent's box (right/left within 1px);
  long words wrap (`overflow-wrap:anywhere` where needed); the 3B harness containment helper is reused.
- **R ⚙ + 👁** `html[dir=rtl]`; "back" arrows point right and "next/forward" arrows point left in Arabic; steppers,
  progress bars and sliders run right-to-left; phone numbers, prices and times are not reversed (bidi isolation).
- **E ⚙** Visible text inside `main`, dialogs and toasts contains no Latin word of ≥ 3 letters except an allowlist:
  user-entered names/messages from seed data, file names, email addresses, `SAR` only where the approved currency symbol
  is not yet available. Status words, buttons, labels, errors and notifications must be Arabic.
- **D 👁** Prices through `tf-price` (amount and currency order per locale); dates with Arabic month names in the
  viewer's time zone; times with «ص/م»; relative times in Arabic; countdowns legible and never negative.
- **T ⚙** Every visible `button`, `a`, `input`, `select`, `[role=button]` in `main` has a box ≥ 44×44 CSS px (inline text
  links inside paragraphs excepted).
- **P ⚙** The screen's filled primary button (`.tf-button:not(.tf-button-ghost)` first in DOM order) intersects the
  viewport on load, or is inside the sticky action bar.

## Preconditions
- Seed scenarios for every state in the matrix (extend `scripts/dev/E2ESeed/Program.cs` where missing).

## Happy path
1. Run `tests/browser/ux06-arabic-phone.e2e.mjs` (Playwright, viewport 390×844, `isMobile`, `hasTouch`,
   `deviceScaleFactor: 3`, locale path `/ar`).
2. For each matrix row and state: navigate as the right user, run H, C, R, E, T, P checks, save a screenshot
   `docs/audits/ux06-<date>/<row>-<state>.png`.
3. A reviewer checks the 👁 assertions on the screenshots and ticks the matrix in the audit report.
4. Defects inside the existing design are fixed in this ticket with a spec; others become new tickets.
5. Re-run until every applicable cell is ✅.

## Negative cases
| Case | Handling |
|------|----------|
| A state cannot be seeded | Add the seed; if impossible without a domain change, record the gap in the report (no fake data in production code) |
| A defect needs a redesign | New ticket (Backlog), cell marked ❌ with the ticket id; UX-06 cannot be Done while a V1 customer screen has ❌ unless the Product Owner accepts it in writing |
| Flaky timing (countdowns, realtime) | Use the test clock/seeded times, not sleeps |
