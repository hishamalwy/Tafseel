## Actor
Student, Teacher, Quality Reviewer, Admin (signed in); Visitor (public header).

## Problem
Primary navigation today (`DASHBOARDS` in `features/dashboards/models/dashboard.ts`, rendered by the generic dashboard
sidebar and `WorkspaceShellComponent`) is:

| Role | Primary items | Tabs |
|------|---------------|------|
| Student | 9 | 2 |
| Teacher | 11 | 8 |
| Quality | 3 | — |
| Admin | 7 | 24 |

It duplicates paths (orders appear in My learning, Payments and Overview; sessions in Sessions, Payments and Overview)
and puts settings, notifications and V1.1 features in primary navigation
([UX_PRINCIPLES §5–§6](../../product/UX_PRINCIPLES.md#5-current-navigation-audit-of-bec03a8)). Gate 2 limits:
Student ≤ 5, Teacher ≤ 6, Quality ≤ 2, Admin ≤ 6.

## User goal
As any signed-in user, I want a short, stable set of destinations named in my own words, with the rest reachable from
the place it belongs, so that I always know where to go.

## Business rule
No new rule. Terminology follows [Contract §3](../../product/TAFSEEL_PRODUCT_CONTRACT.md#3-terminology) — the UI uses simple
words for contract terms:

| Contract term | Who controls it | UI word (AR / EN) |
|---------------|-----------------|-------------------|
| Catalog Service | Admin | Admin: «الخدمات والأسعار» / "Catalog & pricing" |
| Teacher Offering | Teacher | Teacher: «خدماتي» / "My services" — always with the sentence «اختر من خدمات تفصيل وحدّد سعرك ضمن الحدود المسموحة» / "Choose from Tafseel's services and set your price within the allowed range" |
| Teacher Offer (bid) | Teacher → Student | Student: «عروض المعلمين» / "Teachers' offers"; Teacher: «عرضي» / "My offer" |
| Learning Request | Student | «طلب» / "Request"; Open Request «طلب مفتوح» / "Open request" |
| Order | both | «طلب عمل» / "Order" (never «طلب شراء») |
| Live Session Booking | both | «جلسة مباشرة» / "Live session" |

The UI never suggests a teacher creates a Catalog Service ("Create service", «أنشئ خدمة» are forbidden labels).

## Business states
None (navigation). Deferred features stay reachable only where they are V1.

## Preconditions
- `UX-01`, `UX-02` homes exist; `UX-04` vocabulary; `UX-05` canonical marketplace paths.
- Existing screens: `/teachers`, `/requests/new`, `/messages`, `/disputes`, teacher setup screens, generic dashboard
  sections (reused for lists until replaced).

## Happy path
1. The user signs in and lands on their home.
2. Primary navigation shows exactly the destinations below, in order, with the active one highlighted.
3. Header shows notifications bell, account menu and language switch.
4. Old section URLs redirect to their new place; notification and legacy links keep working.

### Notifications bell (all roles)
- Icon button with a dot when the first page has any `readAt = null` item. The dot shows «9+» style counts only up to
  the page size; no exact unread count is claimed.
- Panel (a sheet at 390px): the latest 20 as one-line rows with `UX-04` type copy and relative time; tap marks it read
  and follows its `link` (existing safe-link rule, `dashboard.ts` notification link guard). «تعليم الكل كمقروء» /
  "Mark all as read".
- Empty state: «لا توجد إشعارات» / "No notifications".

## Negative cases
| Case | Behaviour |
|------|-----------|
| User opens a hidden (V1.1) section URL | Redirect per table; never a blank tab |
| User has two roles (e.g. Admin + Teacher) | Existing role-home rule; navigation of the current workspace only |
| Bell load fails | Bell stays without dot; panel shows «تعذّر تحميل الإشعارات» + retry |
| Notification link is external/unsafe | Existing guard drops it; the row only marks read |
| Unknown `view` or chip query | Treated as "All" |

## Authorization
Unchanged. Navigation only hides destinations; every route keeps its guard (`authenticatedGuard`, `roleGuard`) and every
API its policy. Hidden Admin routes remain protected by `PlatformSettings.Manage` etc.

## UX
- **Entry point:** workspace shell (all signed-in pages), public header.
- **Information hierarchy:** primary destinations → sub-navigation only inside "My teaching setup", Admin areas and
  "My requests & orders"/"Work" chips → header utilities.
- **Primary CTA per state:** navigation has no CTA; the home of each role owns the primary action.
- **Wording (AR / EN):** tables above. Arabic first; no English words in Arabic navigation.
- **Mobile (390px):**
  - existing shell pattern (menu drawer) with the reduced list; bell and account visible in the top bar;
  - active destination announced (`aria-current`); drawer items ≥ 44px;
  - chips scroll horizontally **inside their own row only** (the page never scrolls sideways);
  - RTL: the drawer opens from the right.
- **Loading / empty / error / not-available states:**
  - the merged lists reuse `UX-04` cards;
  - empty chips: «لا يوجد ما يحتاج إجراء» / «لا توجد أعمال جارية» / «لا توجد عناصر منتهية» (and teacher equivalents) with the
    role's start CTA («اطلب شرحاً» for students, «طلبات مفتوحة» for teachers);
  - list error with retry;
  - bell states above.
- **Confirmation dialogs:** none.
- **Gate question:** yes — ≤ 6 plain-word destinations per role, each matching a goal the user already has; the rest is
  where they would look for it.

Error codes the UI must explain: none new.
