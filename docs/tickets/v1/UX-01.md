## Actor
Student (signed in, role Student).

## Problem
Student Overview (`/student/overview`, `AppRoutes.StudentHome`) is the generic dashboard with four sources —
`/learning-requests/mine?pageSize=50`, `/orders/mine?pageSize=50`, `/live-sessions/mine?pageSize=50`,
`/notifications?pageSize=100` (`features/dashboards/models/dashboard.ts:36`) — merged into one grid of up to
~250 identical cards with numeric statuses, a search box and Refresh, and no priority
([UX_PRINCIPLES §6.2, §6.4](../../product/UX_PRINCIPLES.md#62-student)). A student who must pay before a
reservation expires, or review a delivery, has to find it among every notification and historical item.

## User goal
As a student, I want my home to tell me first what needs my attention now, then what is in progress and my
next live session, and give me an easy way to start something new — so that I never miss a payment, a
teacher's question or a delivery.

## Business rule
No new rule. The home only presents existing states; each action is performed on the item's own screen,
where the server decides:
- Contract §3.3 (clarification: student replies; cancel), §3.5 (reservation 120 min; release/expiry),
  §3.6 (pay accepted order; review delivery: complete or ask for a revision while revisions remain;
  auto-completion), §3.8 (live sessions: pay, join window 15 min before/after, mutual settlement — the other
  party confirms before `outcomeReviewDeadline`; reschedule proposed by one party, answered by the other),
  §3.12 (non-delivery report when overdue), §3.13 (review a completed paid order once).
- DEC-02 / `UX-09`: an accepted direct order whose agreed price differs from the listed price shows that on
  the order and checkout screens; the home card shows only the amount to pay.

**Current work** (waiting for someone else), one card each, newest first:
request `0 PendingTeacherReview` («بانتظار المعلم»), request `5 OpenForOffers` with no offers («يستقبل العروض»),
order `0 + Paid` («تم الدفع — بانتظار بدء المعلم»), order `1 InProgress` («قيد التنفيذ · التسليم {date}»),
order `3 RevisionRequested` («طُلب تعديل»), session with a reschedule the student proposed («بانتظار رد المعلم»),
sessions `8 TeacherNoShowPending` («بانتظار رد المعلم»). CTA on each: «افتح» / "Open".

**Upcoming live session:** the `1 Confirmed` session with the nearest `startsAt` > now + 15 min.

**Not on the home:** declined, cancelled, expired, converted and completed items (except A12); payment
history; saved teachers; settings; notifications list (bell, `UX-03`); reviews list; disputes list (a
dispute appears only as A10 or on the item's screen); raw fields.

**Card priority rules**
1. Section order is fixed: Action required → Current work → Upcoming session → Start something.
2. Action cards sort by row number (A1 first), then by earliest deadline (`paymentReservationExpiresAt`,
   `outcomeReviewDeadline`, `startsAt`, `agreedDeliveryAt`), then newest `createdAt`.
3. At most **3** action cards; if more, «عرض كل ما يحتاج إجراء ({n})» / "See everything that needs you ({n})" →
   `/student/requests?view=action` (list from `UX-03`).
4. At most **3** current-work cards, then «عرض كل طلباتي» / "See all my requests" → `/student/requests`.
5. One item appears once: a request that became an order is shown only as the order; the order is found by
   `learningRequestId`; an A5 order hides its accepted request.
6. A live countdown (A2) never shows a negative time.

## Preconditions
- Student signed in. `UX-04` status vocabulary available.
- Existing screens: checkout, request detail, offers, order detail, live session.

## Happy path
1. The student signs in or opens «الرئيسية» / "Home" (`/student/overview`).
2. The home loads the three lists in parallel.
3. With a delivered order and an accepted unpaid order, the student sees «أكمل الدفع…» (A5) above «وصل التسليم…» (A8).
4. The student taps «ادفع الآن» and lands on checkout for that order.
5. Returning home, the paid order appears under Current work («تم الدفع — بانتظار بدء المعلم»).

**New student (no requests, orders or sessions):**
1. The home shows the welcome and the two start cards only.
2. «ابحث عن معلم» → `/teachers`; «اطلب شرحاً» → `/requests/new` (request-mode choice).

## Negative cases
| Case | What the student sees |
|------|------------------------|
| One of the three calls fails | Sections from the other calls render; an inline notice «تعذّر تحميل بعض بياناتك» / "Some of your items couldn't load" with «إعادة المحاولة»; the empty "nothing needs your attention" message is **not** shown while any source failed |
| All three fail | Error state (below) |
| Reservation expires while the home is open | A2 card disappears at 0 and the requests list refetches (the item returns as A11/current work) |
| `totalCount > 50` for a list | Only the newest 50 are classified; "See all my requests" is always shown (see API note) |
| Student opens a CTA whose state changed meanwhile | The item's own screen shows the current state and next step (existing behaviour) |
| 401 | Session handling → sign-in → back to home |
| Teacher/Admin on `/student/overview` | Existing role guard (`student/:section`) |

## Authorization
`/learning-requests/mine` and `/orders/mine` require role Student; `/live-sessions/mine` requires
`SessionsManageOwn` and returns only sessions where the caller is a participant. Each response contains only the
caller's items. The home shows no other student's data and no teacher-private fields (`teacherNet`,
commission) — those fields are not rendered even when present.

## UX
- **Entry point:** after sign-in (`AppRoutes.StudentHome` = `/student/overview`); Student navigation item 1
  «الرئيسية» / "Home" (`UX-03`); payment return (`DefaultReturnPath`).
- **Information hierarchy:**
  1. Greeting line «أهلًا {firstName}» / "Hi {firstName}" (one line, no card).
  2. **Action required** — heading «يحتاج انتباهك» / "Needs your attention"; ≤ 3 cards.
  3. **Current work** — heading «قيد التنفيذ» / "In progress"; ≤ 3 cards.
  4. **Upcoming live session** — heading «جلستك القادمة» / "Your next session"; 1 card: teacher, service,
     «{weekday} {date} · {time}», «تبدأ بعد {relative}», CTA «تفاصيل الجلسة» / "Session details" → `/live-sessions/:id`.
     Hidden when none.
  5. **Start something** — heading «ابدأ طلبًا جديدًا» / "Start something new"; two side-by-side cards
     (stacked at 390px): «ابحث عن معلم» / "Find a teacher" and «اطلب شرحاً» / "Post a request".
- **Primary CTA per state:**

  | State | Primary CTA |
  |-------|-------------|
  | ≥ 1 action card | The first action card's CTA is the only filled button; others are outline buttons |
  | No action, some current work | No filled button; the Start cards are the invitation |
  | New student | The two start cards (equal choice cards, the same pattern as the `/requests/new` choice) |
  | Error | «إعادة المحاولة» / "Try again" |

- **Wording (AR / EN):** tables above, plus:

  | Key (proposed) | Arabic | English |
  |----------------|--------|---------|
  | `sh_nothing_needed` | لا يوجد ما يحتاج انتباهك الآن. | Nothing needs your attention right now. |
  | `sh_welcome_title` | أهلًا {firstName}، كيف نساعدك اليوم؟ | Welcome, {firstName}. How can we help today? |
  | `sh_start_find` | ابحث عن معلم | Find a teacher |
  | `sh_start_find_body` | تصفّح المعلمين المؤهلين واطلب من المعلم الذي تختاره. | Browse qualified teachers and ask the one you choose. |
  | `sh_start_post` | اطلب شرحاً | Post a request |
  | `sh_start_post_body` | صِف ما تحتاجه، ثم اطلب من معلم محدد أو استقبل عروضًا من عدة معلمين. | Describe what you need, then ask one teacher or receive offers from several. |
  | `sh_partial_error` | تعذّر تحميل بعض بياناتك. | Some of your items couldn't load. |
  | `sh_error` | تعذّر تحميل صفحتك الرئيسية. | We couldn't load your home. |
  | `sh_retry` | إعادة المحاولة | Try again |

  Status words and CTA verbs come from `UX-04`. Never shown: ids, "Order #", "Payment status", "Count", search, Refresh.
- **Mobile (390px):**
  - single column; 16px side gutter; cards full width;
  - action card ≈ 96–120px (title ≤ 2 lines, one supporting line, CTA ≥ 44px);
  - **max content above the fold (390×844): greeting + 3 action cards**, or for a new student welcome + both
    start cards;
  - no horizontal scroll; countdown uses tabular digits; Arabic numerals and dates via the app formatter;
  - no sticky elements on the home.
- **Loading / empty / error / not-available states:**
  - loading: greeting and three skeleton cards under "Needs your attention";
  - empty with history: `sh_nothing_needed` + Start section;
  - new student: welcome + start cards (no empty section headings);
  - partial error: rendered sections + inline notice;
  - full error: `sh_error` + retry;
  - not-available: role guard.
- **Confirmation dialogs:** none on the home (payments, confirmations and reports are confirmed on their screens).
- **Gate question:** yes — the first thing on the screen is a sentence saying what to do and a verb button; statuses
  are everyday words; there is nothing to search or decode.

## API contracts
No new API contract; presentation/composition only.

| UI action | Endpoint | Verb | Request | Headers / concurrency | Response | Resulting server state |
|-----------|----------|------|---------|-----------------------|----------|------------------------|
| Load home | `/api/v1/learning-requests/mine?page=1&pageSize=50` | GET | — | Bearer | `PagedResult<LearningRequestDto>` (uses `id, title, status, sourcingMode, teacherDisplayName(+English), paymentReservationExpiresAt, offerCount, clarifications, createdAt, resultOrderStatus`) | none |
| Load home | `/api/v1/orders/mine?page=1&pageSize=50` | GET | — | Bearer | `PagedResult<OrderDto>` (uses `id, learningRequestId, requestTitle, status, paymentStatus, studentTotal, currency, agreedDeliveryAt, teacherDisplayName, reviewCanSubmit, hasReview, canReportNonDelivery, createdAt`) | none |
| Load home | `/api/v1/live-sessions/mine?page=1&pageSize=50` | GET | — | Bearer | `PagedResult<LiveSessionDto>` (uses `id, title, status, startsAt, endsAt, totalPrice, currency, teacherDisplayName, proposedStartsAt, rescheduleRequestedById, outcomeReviewDeadline, studentId`) | none |
| Greeting / viewer id | `/api/v1/auth/me` (already loaded by the session) | GET | — | Bearer | current user | none |
| Tap a CTA | client navigation only | — | — | — | — | none |

**Endpoint audit conclusion — no home endpoint.** The three existing lists carry every field the classification
needs. Each is newest-first (requests and orders by `createdAt`, sessions by `startsAt`) and capped at 50 per
page. Items requiring action are recent by nature: a reservation lasts 120 min, a delivered order auto-completes
7 days after the last delivery, a session outcome must be confirmed within 24 h. A student would need more than
50 newer items for one to be missed, and it would still be reachable from "My requests & orders" and from its
notification. This is not a demonstrated correctness or performance problem, so a
home aggregation endpoint is **not** justified. Revisit only if production data shows students with > 50 items in
30 days (then prefer a `status` filter on the existing lists, as `learning-requests/assigned` already has).

Error codes the UI must explain: none new (list reads); network/5xx → partial or full error state.

## Acceptance criteria
- [ ] AC1 Sections render in the order Action required → Current work → Upcoming session → Start something.
- [ ] AC2 Each A1–A12 condition produces its card with the AR/EN copy and CTA route above; items not listed never appear.
- [ ] AC3 Action cards follow the priority rules; at most 3 action and 3 current-work cards, with "see all" links.
- [ ] AC4 An item appears once (request converted/accepted into an order shows only as the order).
- [ ] AC5 The A2 countdown updates each minute (each second under 5 min) and removes the card at expiry, then refetches requests.
- [ ] AC6 New student sees welcome + two start cards; Find a teacher → `/teachers`; Post a request → `/requests/new`.
- [ ] AC7 Partial failure never shows "Nothing needs your attention"; full failure shows retry.
- [ ] AC8 No notifications list, payments, saved teachers, settings, reviews or disputes list, search box, Refresh, id or numeric status on the home.
- [ ] AC9 At 390px Arabic: greeting + 3 action cards visible above the fold; no horizontal scroll; touch targets ≥ 44px.
